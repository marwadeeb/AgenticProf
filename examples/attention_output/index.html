The idea

Attention compares a query with every key by a dot product, turning the scores into weights with a softmax, then mixes the values using those weights. Dividing the scores by dk keeps them from growing so large that the softmax becomes almost a hard pick with tiny gradients.

Why it matters. This one equation is the core operation of the Transformer, and the 1/dk factor is the small detail that makes training stable when the key dimension dk is large.
Attention(Q,K,V)=softmax(QK⊤dk)V
Section 3.2.1, Equation 1

What each symbol means

Qquery matrix, one query per row, dk columns
Kkey matrix, one key per row, dk columns
Vvalue matrix, one value vector per row, dv columns
dkdimension of queries and keys (number of columns of Q and K)
QK⊤matrix of raw dot-product scores, entry (i,j) is query i dotted with key j
dkscaling factor that counteracts large dot products
softmaxrow-wise normalisation: esij/∑jesij

Guided explorations

Exploration 1

All-equal scores give uniform weights

Do
Set every entry of Q to 1 (Q = [[1,1,1],[1,1,1]]).
Guess
What do you expect, and why?
See
In the weights panel every bar for a query has the same height, and the readout shows each weight = 1/3 ≈ 0.333 with row sum 1.000. The output rows equal the column means of V, (0.667, 0.667).
Why
Each query dots to the same value with every key, so all scores sij are equal. Softmax of equal scores is es/∑jes=1/n regardless of s, so the scaling cannot change the weights here.
Then
Turn the scaling toggle off: the weights stay at 1/3, confirming that 1/dk only rescales scores, not uniform weights.
Exploration 2

One dominant score concentrates the weight

Do
Set Q = [[3,0,0],[0,0,0]] so query 1 scores 3 against key 1 and 0 against the others.
Guess
What do you expect, and why?
See
Query 1's weight bars peak on key 1 (about 0.88 with scaling on, since e3/3≈5.65 versus 1 for the others), and its output row moves toward v1=(1,0). Query 2 stays uniform at 1/3.
Why
The softmax weight is esij/∑jesij, so a larger score difference pushes weight toward the largest score. Dividing by dk shrinks that difference, keeping the distribution softer.
Then
Raise the score gain to 8: the top weight approaches 1 and the output row approaches v1 exactly, showing the sharp, low-gradient regime the paper warns about.

Assumptions, limits and pitfalls

What the idea quietly assumes, where it stops working, and the trap most learners fall into.

A
Assumption

The excerpt assumes queries and keys share dimension dk so that QK⊤ is defined, and that softmax is applied row-wise (each query normalises over all keys). Our playground keeps dk equal for Q and K and normalises each row.

L
Limitation

We use tiny hand-editable matrices, not the paper's trained models, so no number here reproduces the paper's experiments. The gain slider only emulates the effect of a larger dk; it does not change the actual dimension.

?
Common misunderstanding

Scaling by 1/dk does not change which key wins, only how sharply the weights concentrate. With all-equal scores the weights are 1/n whether or not you scale, as the first exploration shows.

Read the source excerpt this page was generated from (122 words)

Section 3.2.1, Scaled Dot-Product Attention (paraphrased for practice). An attention function maps a query and a set of key-value pairs to an output. Queries and keys have dimension d_k and values have dimension d_v. For each query we take its dot product with every key, divide each by √d_k, and apply a softmax to obtain weights on the values. With queries packed into a matrix Q, keys into K and values into V: Attention(Q, K, V) = softmax(QKᵀ/√d_k) V (Equation 1). The authors compare this with additive attention and with unscaled dot-product attention. They suspect that for large d_k the dot products grow large in magnitude, pushing the softmax into regions with extremely small gradients, and scale by 1/√d_k to counteract this.
